## 变更记录

### r27（2026-09-14 09:28）
1. **修：`mount-status` 竞态。** 重挂瞬间旧实例异步写 `stopped`，会把新实例的 `running` 覆盖掉，造成"通道在跑、状态却是 stopped"的假象（本次排障就被它误导过一次）。现在每次挂载带一个 `runId`，终态写入前先认领：`runId` 不匹配就拒绝写入并记一行日志。已实测到"忽略过期的 stopped 写入"。
2. **加：自愈看门狗**（`tools/watchdog.mjs`，配置 `watchdog`，默认开）。插件自身不可能自救——它随 fiber 卸载就停跑了，所以由一个**独立进程**（挂载时 `detached + unref` 拉起，pidfile 去重）每 20s 检查：`stage` 不是 `running`，或 `running` 但记的 pid 已不存在 → 连续 3 次判定后**先移除行、等 10s、用新 id 重新插入**（换 id 是必须的：同一 id 换 name 会"拆得掉、插不回"）。安全阀：`watchdog.off` 开关、patch 60s 内被写过则跳过、动手后 5 分钟冷却、任何 profile 都没这一行时视为人工卸载不再干预。已实测一次完整自愈：3 次判定 → 重挂 → 15s 内确认 `running`。

### r26（2026-09-14 08:22）
1. **修：浏览器聊天区看不到微信发来的原文。** 入站消息原先用 `source = { kind:'plugin', form:'notice', summary:'inbound WeChat message' }`，Web 端会把这类消息渲染成**折叠的上下文行**（`ui-chat` `ContextBody` 的 `case 'notice'`），行上只显示 summary，微信里真正发的内容藏在折叠体里——表现就是"只能看到 dsh 给微信的回复"。现改为 `source = { kind:'user' }`，与浏览器里亲手输入的消息同构，渲染成**完整气泡**。
2. **修：微信会话在浏览器侧栏里被彻底隐藏。** DSH 的归档集合 `workspaceRegistry.archivedSessionIds` 语义是"从**所有**分组和搜索里隐藏"，而全仓**只有归档、没有反归档 API**。新增配置 `ensureSessionVisible`（默认开）+ 两道兜底：每次复用/新建会话时取消该会话的归档；挂载时把 `weixin-` 前缀的历史会话整体捞出归档集合。启动日志会打印捞出清单。

## 一、一句话结论

它是一个 **DSH 宿主平面的外挂插件**（不属于 DSH 官方包，靠 `cordis.patch.yml` 里一行 `insert` 挂上去），把腾讯的 ilink 机器人协议接成 DSH 的一个入口：**你在微信里发消息 = 在一个真实的 DSH 会话里下指令**，权限拉满、文件双向通、图片和视频能进上下文。

---

## 二、它是怎么接上去的

```
微信 App
   ↓ 你发消息
腾讯 ilink bot 服务（ilinkai.weixin.qq.com）
   ↓ getUpdates 长轮询（35s 超时，服务端可自适应调整）
dsh-weixin-channel（DSH 宿主进程内，一个常驻循环）
   ↓ bridge.processMessage
DSH agents（创建 / resume 会话 → followup 驱动一轮对话）
   ↓ 回复文本 + 文件
sendmessage / CDN 上传（novac2c.cdn.weixin.qq.com）
   ↓
微信 App 收到消息
```

- 平面：host 组合。插件**不发布任何 service**，纯消费者 + 后台循环。
- 规模：**一个长轮询连接**，多个微信用户 → 各自独立会话。
- 挂载方式：`%DSH_HOME%\profiles\web\cordis.patch.yml` 里一行
  `insert: [{ id: weixin-channel-5faf764c, name: "./dsh-weixin-channel-5faf764c/index.mjs", config: {...} }]`
- 部署方式：`tools/deploy.mjs` 按内容哈希生成版本目录并改写挂载行（因为加载器按 URL 缓存模块），属于**热挂载**，不需要重启 DSH。

### 源头与许可

从腾讯官方 `@tencent-weixin/openclaw-weixin@2.4.8`（Tencent，MIT）移植。协议层（ilink 请求/响应、CDN 加解密）逐行保留，改动集中在**「谁来处理这条消息」**：原实现交给 openclaw，本插件交给 DSH 会话。

## 三、会话模型（你最关心的部分）

| 行为 | 现在的实现 |
| --- | --- |
| 默认模式 | **一条微信对话 = 一个 DSH 会话，跨消息长期复用**。映射持久化在 `%DSH_HOME%\weixin\sessions.json` |
| 插件重启后 | 映射不丢，用 `resumeSessionId` 续上原会话（并补传 provider/model，规避历史 `{{model}}` 报错） |
| 想开新对话 | 微信里单发「新对话」「开新对话」「重置对话」「/new」「/reset」。**只解绑映射，不销毁旧会话** —— 旧会话仍能在 DSH 会话列表里查到；下一条消息才在新会话里回答 |
| 权限 | 每个会话都设 `danger-full-access`（沙箱满权限 + approval=never），**不弹任何审批** |
| 会话标题 | 按消息预览自动改名，便于在 DSH 会话列表里认 |
| 决策方式 | **只能纯文本**。`ask_user_question` 和 `exit_plan_mode` 已从微信会话的工具集中**物理移除**（不是靠提示词约束），二者在本部署里都会把问题交给 Web 客户端挂起、在微信侧表现为静默卡死。同时注入通道说明，要求用编号列表提问 |
| 并发 | 入站**串行**处理（微信是对话式输入，并发会打乱体验）；单轮上限 15 分钟；处理期间持续发「正在输入」 |
| 欢迎语 | 插件每次挂载会主动问候一句（既是反馈，也是出站链路的自证）。可用 `DSH_WEIXIN_NO_GREET=1` 关掉 |

## 四、你发给它（入站能力）

| 你在微信里发 | 通道怎么处理 | 效果 |
| --- | --- | --- |
| **文字** | 原样送进会话 | 正常回答（就是你现在这样用） |
| **图片** | 从 CDN 下载 + AES 解密 → 存为附件 → 作为**原生图片**进上下文 | 我**能直接看到画面** |
| **文件** | docx / xlsx / pptx / pdf / zip 等，下载解密后存盘 + 作为附件进上下文 | 我**能读内容**；并回一句「文件已保存：名字（字节数）」 |
| **语音** | 优先用微信服务端给的**转写文本** | 有转写 → 当文字处理；无转写 → 只存下 SILK 音频，**我听不了**，会明确告诉你改用文字 |
| **视频** | **默认只下载保存，不抽帧、不分析**（按你「省 token」的明确要求） | 回一句「已保存，要看请说分析视频」；本地路径记入视频历史 |

### 视频：按需分析（唯一一条会花 token 的路径）

- **触发**：`/分析`（最近一条）、`/分析 2`（倒数第二条）、`分析视频`、`/analyze`、`看看视频`
- **改抽帧数**：`/frames N`（1~16，也认「帧数 N」）。默认 **3 帧** + 场景变化处最多**补 2 帧**
- **解码链（三级降级，任一环失败都不影响视频保存）**：
  1. `ffmpeg`（`fps` + `tile` 滤镜，一次编码直接出宫格，没有逐帧解码开销）
  2. Media Foundation（`tools/mf-frames.ps1`，顺序解码 + 时间窗采样；MF 不能 seek）
  3. Shell 缩略图兜底
- **产物**：一张 N 格宫格图，同时做两件事 —— (a) 作为原生图片进本轮上下文交给我分析；(b) 存成附件后**回发给你看**。也就是说：**我看到的画面，你也能看到**，便于你判断我有没有看错。
- **只报元数据（不花 token）**：`/视频信息`（文件名/大小/时长/本地路径）、`/视频列表`（最近几条）
- **历史**：每个用户最多留 **5 条**，**仅进程内存**，插件重启即空（视频文件本身在磁盘上，路径可从 `channel.log` 找回）

## 五、它发给你（出站能力）

在回复里**单独占一行**写 `MEDIA:<绝对路径>`，该行不会作为文字发出，文件会被上传并推送给你：

```
文件已生成，见下。
MEDIA:D:\deepwork\手机端\报告.docx
```

| 类型 | 支持 | 说明 |
| --- | --- | --- |
| 文本 | ✅ | 超过 4000 字按段落边界切分多条发送 |
| 图片 | ✅ | 按扩展名自动选 `image_item` |
| 文档 / 表格 / 演示 / PDF / 压缩包 | ✅ | Word、Excel、PPT、PDF、ZIP 等**已实测通过** |
| 视频（我主动发给你） | ❌ **未接入** | 上行（你发我）已通；下行还没做完端到端验证 |

路径必须是**绝对路径且文件真实存在**，否则发送失败并把错误回报给你（不会静默）。

### 出站链路与守卫（踩坑最多的一段，也是稳定性的核心）

所有出站都必须经过 `lib/outbound.mjs` 的守卫：

1. **节流**：两次发送之间最小间隔 1.5s（防突发送触发限流 —— 曾用脚本密集连发 10 分钟全失败）
2. **令牌新鲜度**：`context_token` 约十余分钟失效。缓存年龄超过 10 分钟就**直接不带令牌发送**（实测：过期的令牌比没有令牌更糟，会回 `ret=-2 prepare failed`）
3. **降级重试**：带令牌失败 → 自动改用**不带令牌**发送；代价是不并入原会话上下文，但总比发不出去好
4. **断路器**：连续 3 次可恢复失败 → 进入 5 分钟冷却
5. **台账**：每笔出站写 `%DSH_HOME%\weixin\media-log.jsonl`
6. **发送前自检**：把刚上传的对象**下载回来逐字节比对**。`ack-header` 模式下取图路径与服务端不同、自检给不出结论，此时只告警不阻塞（否则会误杀已被验证可用的配方）

**媒体引用配方**（三处关键，错一个对方就打不开，已验证）：
- 引用参数取自**上传响应头 `x-encrypted-param`**（用 `upload_param` 会「发出去了但打不开」）
- `aes_key` = **base64(32 位 hex)**（不是 base64(原始 16 字节)）
- 必须带 `encrypt_type: 1`；**绝不能带 `full_url`**（带上就不投递）

## 七、稳定性、安全与可观测性

- **白名单**：配置里的 `allowFrom` ∪ 状态目录里持久化的自助配对名单（你的号已在其中）。名单外一律拒绝；`autoPair` 目前关闭。`/pair` 可自助加入（供内网自用）。
- **磁盘审计日志** `%DSH_HOME%\weixin\channel.log`：收发每一步都留痕 —— 这是外部判断「到底收没收到、发没发出去」的**唯一可靠证据**（宿主日志在另一个终端里）。
- **挂载探针** `%DSH_HOME%\weixin\mount-status.json`：记录 `stage` / `build` / `pid` / `accountId`，用来判断插件是否真的装上、热重组后模块有没有被重新导入。
- **侧栏可见性兜底**：归档 = 在所有分组/搜索里彻底隐藏，且 DSH 没有反归档 API。`ensureSessionVisible`（默认开）会在每次复用/新建会话时取消该会话的归档，并在插件挂载时把 `weixin-` 前缀的历史会话从归档集合整体捞出。
- **⚠️ 已知失效模式：热重组后行可能挂不回来。** 实测一次（2026-09-14 08:12:52）通道被卸载后**再没挂回来**：宿主进程没重启、`cordis.patch.yml` 也没被改写，但**生效的组合里那一行丢了** —— 微信侧完全静默。这正是 `deploy.mjs` 注释里记过的"同一 id 只换 name 时，重组会移除旧行却插不进新行"。**恢复办法：让内容变一下再 `node tools/deploy.mjs`（换 URL 就会重新导入挂载）**，或先 `retoggle`（移除→等待→重插）。r27 起由**独立进程看门狗**在约 60s 内自动换新 id 重挂（见变更记录 r27）。
- **r27 已修**（终态写入现在带 `runId` 认领）：原先 `mount-status.json` 的 `stopped` 由旧实例异步写入，重挂瞬间可能覆盖新实例写的 `running`，出现"通道其实在跑、状态却是 stopped"的假象（本次排查就被它误导过一次）。
- **未登录可用**：允许「先挂载、后扫码」，未登录时每 5s 轮询，扫码成功自动接管。
- **长轮询自愈**：连续 3 次失败 → 30s 退避，否则 2s 重试；失效令牌 → 暂停 30 分钟再试。

## 八、已知边界（诚实清单）

1. **主动发视频未接入**（下行）。上行已支持。
2. **语音没有本地转写**：服务端不给转写时只能拿到 SILK 音频，我无法直接听。
3. **视频历史与抽帧设置只在内存**：插件重启即清空。
4. **`tools/*.mjs` 手工脚本绕过守卫**：`send-test.mjs` / `send-file-test.mjs` / `cdn-*.mjs` 直连 ilink，只能手动排障用，不要放进自动化。
5. **尚未查清**：2026-09-13 21:31 用 `upload_param` 的那次异常；「限流」与「令牌消耗」两个因素还没分离；`taskid` 是否必填未知；各类型文件大小上限未知。
6. **`message_id` 只代表服务端收下，不代表送达** —— 判断送达必须看接收端。
7. **只做单聊**，未接群聊。
8. **r26 之前的历史消息在浏览器里仍是折叠行**：本次只改了新消息的渲染形态，已存在的旧记录不会重写（点开折叠行仍能看到内容）。
9. **热重组的"行丢失"失效模式**（见第七章）尚无自动恢复，需人工 redeploy。

## 结论

**能用了，而且双向通**：文字、图片、文件（Word/Excel/PPT/PDF/压缩包）、语音（有转写时）进得来；文字、图片、文档出得去；会话长期复用、权限拉满、决策只走文本；视频按你的要求默认只存不分析、要分析时抽宫格且把宫格回发给你。

**还没做完的**集中在四件事：主动发视频、语音本地转写、视频状态持久化、限流与稳定性的深挖。
