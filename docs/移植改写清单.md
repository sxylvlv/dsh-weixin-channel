## 四、DSH 侧对应物（已核证据）

| OpenClaw 概念 | DSH 对应物 | 证据 |
|---|---|---|
| `channelRuntime.routing` / `session` / `reply` | **`ctx.agents`**：`create()` / `resume(id)` / `get(id)` / `followup()` / `whenIdle()` / `cancel()` | `packages/core/agent/README.md:32,47` |
| 流式助手输出 | 事件 **`agent/assistant-stream`**（start/chunk/end 帧）；提交后落成一条 `assistant/message` 或 `assistant/attempt` | `packages/core/agent/README.md:67` |
| 入站事件建会话 | `ctx.webhookRuntime`（**本项目用长轮询，不需要**） | `packages/webhook/webhook/README.md` |
| 插件入口 | 出树 ESM 模块：`export const name / inject / Config` + `export function apply(ctx, config)` | `apps/cli/config/examples/github-review/github-ready-review-rule.mjs` |
| 挂载方式 | profile patch 追加一行 `insert:`；模块与 `cordis.patch.yml` 同目录，`name: './xxx.mjs'` | 同上 + `docs/user/guide/github-review.md:38` |
| 可逆副作用 | `ctx.effect(() => ...)` 返回 disposer | 同上 |

**平面判定（重要）**：本插件**属于 host 组合，不属于 agent preset**。理由：它拥有一个进程级长轮询连接，且一个微信账号对应多个 DSH 会话，跨会话共享——符合"有会话平面之外消费者 ⇒ 不能进 preset"的规则。它**不发布任何 service**（纯消费者 + 后台循环），因此**不需要 isolate realm**，patch 里裸行即可。

## 五、移植步骤

1. **vendor**：`npm pack @tencent-weixin/openclaw-weixin@2.4.8` → 解包 → 把 §2.A 的文件拷进 `vendor/`，用一张 import 映射表批量改写（§3 表逐条替换）。
2. **重写 3 个文件**：`index.mjs`（插件入口）、`lib/bridge.mjs`（入站→会话→出站）、`lib/config`（配置）。
3. **挂载**：把 `dsh-weixin-channel/` 放到 `$DSH_HOME/profiles/web/` 旁，把 `cordis.patch.snippet.yml` 的行追加进 `cordis.patch.yml`。
4. **先登录**（不依赖 DSH 运行）：`node bin/weixin-login.mjs` 扫码，token 落到状态目录。
5. **启动验证**：`dsh web`，用白名单内的微信发一条消息，确认收到回复。
